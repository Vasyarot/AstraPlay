Доработка плеера и карточек AstraPlay — 04.11.2026.

Встроенный плеер доработан на существующем Media3 1.4.1: свой контроллер в стиле приложения, прямое воспроизведение файлов и доступных сетевых потоков, очередь серий, продолжение просмотра. Внешние приложения для этого маршрута не запускаются. Нативные карточки показывают сведения конкретного источника; HTML страницы не отрисовывается и JavaScript в карточке не выполняется.

**Что изменено**

- Исправлен маршрут прямого видео из карточки: запись `Kinds.WEB` больше не отправляет выбранный поток обратно в карточку/браузер. Для видео существует явный маршрут `Nav.playVideoQueue`.
- Очередь хранит только метаданные на диске в приватной папке приложения. Ограничения — до 1000 записей, 1 МБ на очередь, 16 файлов. Через Intent передаются ключ и индекс; следующее видео заранее не буферизуется.
- Фильм использует очередь из одной записи. Сериал — очередь доступных эпизодов выбранного сезона. Есть предыдущая/следующая серия, автопереход по настройке приложения, собственная позиция и отметка просмотра у каждого эпизода.
- При сворачивании освобождаются ExoPlayer, декодер и видеоповерхность; при возвращении восстанавливаются текущая серия, позиция и состояние паузы. Обрабатывается новый Intent для `singleTask`-плеера.
- В контроллер добавлены качество, меню, предыдущая/следующая серия, избранное. Меню включает звуковые дорожки, субтитры, скорость, размер кадра и существующий таймер сна. Длинная очередь в меню отображается через RecyclerView.
- Ошибки сети, декодера и отсутствия доступного потока показываются отдельной панелью с повтором, выбором качества и возвратом.
- Основная кнопка использует плеер AstraPlay. Если прямой поток не найден, автоматического открытия веб-плеера нет. По выбранному пользователем варианту есть отдельная кнопка «Плеер источника» для фильма и для подходящих эпизодов.
- При явно выбранном плеере источника загружается его embed, а не полная страница. Наблюдение за доступным HTML5-видео позволяет сохранять позицию и распознавать окончание. У вложенных cross-origin плееров эти данные могут быть недоступны; в таком случае существующая позиция не затирается нулём.
- Карточка использует один вертикальный RecyclerView с заголовком и сериями через ConcatAdapter. Удалено сочетание ScrollView и полностью развёрнутого вертикального списка. Есть постер/заглушка, описание с раскрытием, метаданные, актёры, режиссёр, сезоны, прогресс и отметки серий. Кнопки и фокус используют тему AstraPlay.
- Запросы отменяются при смене карточки/сезона. Исправлена гонка, при которой ответ старого сезона мог заменить выбранный. Файловый кэш карточек получил новое пространство ключей для обновлённого формата.
- Добавлен общий разбор публичных JSON-LD, Open Graph, microdata, HTML5 video/source и явно размеченных плееров. Не выполняется JavaScript для получения описания, не угадываются зашифрованные адреса потоков.
- Смотрим: добавлен разбор списка эпизодов из публичного SSR-состояния `__NUXT_DATA__`, с привязкой к текущему бренду. Одиночное видео фильма не выдаётся за сериал.
- Seasonvar: поддержаны открытые прямые адреса в плейлистах. Для нового движка добавлена загрузка опубликованного в HTML адреса расписания сезонов/серий. Расписание не выдаётся за доступные видеопотоки.
- Сетевой плеер использует Media3 OkHttpDataSource и общий сетевой стек. Cookies выбираются CookieJar для адреса конкретного запроса; Referer передаётся из источника.

**Настройки для слабого телевизора**

На устройстве с небольшим объёмом памяти по умолчанию выбирается профиль до 720p и предпочтение H.264. Целевой буфер сжатых данных — 12 МБ, временные пороги — не более 15/20 секунд, обратного буфера нет. Размер буфера имеет приоритет над длительностью. На остальных устройствах профиль — до 1080p, буфер 24 МБ. Кэш изображений ограничен 8 МБ, размер постера в карточке — 300×450 пикселей, crossfade выключен.

Целевой буфер не является пределом всей памяти процесса: декодер, графика и другие компоненты потребляют память отдельно. Ограничение качества выбирает подходящие доступные дорожки и не перекодирует единственный 4K-файл в 720p. Произвольные кодеки и битрейты на любом ТВ не гарантируются.

Освобождение плеера в `onStop` для API 24+ соответствует [рекомендации Android Media3](https://developer.android.com/media/implement/playback-app). Порог буфера задаётся через [DefaultLoadControl.Builder](https://developer.android.com/reference/androidx/media3/exoplayer/DefaultLoadControl.Builder).

Нативный плеер работает с доступными прямыми медиаресурсами. Там, где источник публикует только собственный плеер, он запускается отдельной кнопкой внутри приложения. Его реклама, ограничения, DRM и особенности JavaScript остаются свойствами источника. Автопереход/позиция такого плеера доступны лишь когда он предоставляет наблюдаемое HTML5-видео. Для остальных сайтов общий парсер обеспечивает основу карточки, но поддержку конкретной разметки и просмотра нужно подтверждать на реальных страницах.

Основные новые файлы: `player/PlaybackPolicy.kt`, `player/VideoQueue.kt`, `data/sources/PublicVideoMetadata.kt`, `res/values/video.xml`, тесты `VideoPlaybackTest`, `PublicVideoMetadataTest`, `NativeVideoTest`. Доработаны существующие `PlayerActivity`, `EmbedPlayerActivity`, `SourceDetails`, `SourceDetailsActivity`, маршрутизация и общий сетевой клиент. Изменения предыдущих помощников сохранены.
